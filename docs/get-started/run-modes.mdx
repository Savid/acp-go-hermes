---
title: Run Modes
description: Choose between the standalone ACP subprocess and the embedded Serve entry point.
---

The adapter runs the same core two ways: as a standalone process an ACP host
launches, or embedded in your own Go program through `Serve`. The native gateway
behavior is identical in both.

## Standalone command

Standalone native mode runs on every supported platform. Hermes runs as the
same operating-system account as `acp-go-hermes`.

An ACP client launches `acp-go-hermes` as a subprocess and speaks ACP over its
stdin/stdout. Stdout carries ACP JSON-RPC only; diagnostics go to stderr.
Input is newline-delimited and framed incrementally to the ACP SDK's 10 MiB
maximum. Oversized or unterminated frames are rejected before lifecycle request
identity is registered or a session can open, and diagnostics never include the
frame body.

```sh
acp-go-hermes -path /usr/bin/hermes -scratch-dir /tmp/acp-hermes
```

## Embedded

Construct an `Agent` for full control, or call `Serve` to run the ACP loop over
a reader/writer pair:

<CodeGroup>
```go
agent := hermesacp.NewAgent(
	hermesacp.WithScratchDir(scratchDir),
)
```

```go
agent := hermesacp.NewAgent(
	hermesacp.WithScratchDir(scratchDir),
	hermesacp.WithHostAuthority(authority),
)
```

```go
err := hermesacp.Serve(ctx, input, output, hermesacp.WithScratchDir(scratchDir))
```
</CodeGroup>

See the [Go API](/docs/reference/go-api) for the full option set.
The host authority is borrowed and handles the native environment, tree
preparation and reclaim, and every managed process launch. A supplied authority
never falls back to ordinary execution.

## Native gateway

For each ACP session, the adapter starts `hermes serve --host 127.0.0.1` with an
isolated `HERMES_HOME` by default and connects to `/api/ws`. Explicit
`-shared-hermes-home` mode uses that exact durable native home instead.

The adapter wraps the dashboard gateway directly, not Hermes' native ACP server
mode.
