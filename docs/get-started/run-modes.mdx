---
title: Run Modes
description: Choose between the standalone ACP subprocess and the embedded Serve entry point.
---

The adapter runs the same core two ways: as a standalone process an ACP host
launches, or embedded in your own Go program through `Serve`. The native gateway
behavior is identical in both.

## Standalone command

An ACP client launches `acp-go-hermes` as a subprocess and speaks ACP over its
stdin/stdout. Stdout carries ACP JSON-RPC only; diagnostics go to stderr.

```sh
acp-go-hermes -path /usr/bin/hermes -home /tmp/acp-hermes
```

## Embedded

Construct an `Agent` for full control, or call `Serve` to run the ACP loop over
a reader/writer pair:

<CodeGroup>
```go NewAgent
agent := hermesacp.NewAgent(hermesacp.WithHome(home))
```

```go Serve
err := hermesacp.Serve(ctx, input, output, hermesacp.WithHome(home))
```
</CodeGroup>

See the [Go API](/docs/reference/go-api) for the full option set.

## Native gateway

For each ACP session, the adapter starts `hermes serve --host 127.0.0.1` with an
isolated `HERMES_HOME` and connects to `/api/ws`. `--skip-build` is passed only
when `HERMES_WEB_DIST` is configured or the default Hermes web dist exists;
otherwise Hermes builds or locates its web assets normally.

The adapter wraps the dashboard gateway directly, not Hermes' native ACP server
mode.
