---
title: Metadata
description: The _meta.hermes vocabulary accepted on requests and emitted on responses.
---

The adapter reads and writes vendor metadata under the `_meta.hermes` namespace.
Unknown keys under `_meta.hermes` are rejected; foreign namespaces are ignored.

## Request metadata

Lifecycle requests accept:

```json
{
  "_meta": {
    "hermes": {
      "options": {
        "model": "provider/model",
        "env": {}
      },
      "rawEvent": {
        "enabled": false
      }
    }
  }
}
```

| Field | Meaning |
|---|---|
| `options.model` | Selects the `provider/model` pair for the session. |
| `options.env` | Per-session environment variables injected into Hermes. |
| `rawEvent.enabled` | Opt the session into `_hermes/rawEvent` notifications. |

No other option keys are accepted; any unsupported field fails with an
invalid-params `{"error":"unsupported"}` response.

## Response metadata

Advertised model config options carry per-model `_meta.hermes` metadata:
`contextWindow`, `maxOutputTokens`, `capabilities` (for example `tools`,
`image`, `audio`), and `supportedEffortLevels` where the model exposes them.
Usage updates may carry `_meta.hermes.messageId`.
