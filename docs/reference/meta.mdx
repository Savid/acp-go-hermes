---
title: Metadata
description: The _meta.hermes vocabulary accepted on requests and emitted on responses.
---

The adapter reads and writes vendor metadata under the `_meta.hermes` namespace.
Unknown keys under `_meta.hermes` are rejected; foreign namespaces are ignored.

Initialize separately advertises reserved `acp-go.dev/` capability keys — the
route capability, the media envelope, local handoff support, and the lifecycle
extension. None of them is part of the Hermes namespace.

Initialize advertises the reserved route capability as
`_meta["acp-go.dev/route"] = {"version":1}`.

`session/prompt` and `session/cancel` require exactly
`{"version":1,"turnNonce":"..."}` under the reserved route key. The nonce is
fresh and unguessable per turn and is at most 4096 bytes.

A `session/prompt` refusal on this key is invalid params (`-32602`) and splits
into two verdicts a host acts on differently:

| Cause | `data` |
|---|---|
| The key is absent | `{"error":"missing","field":"_meta[\"acp-go.dev/route\"]"}` |
| The value is not an object | `{"error":"unsupported","field":"_meta[\"acp-go.dev/route\"]"}` |
| `version` is not `1` | `{"error":"unsupported","field":"_meta[\"acp-go.dev/route\"].version"}` |
| `turnNonce` is empty, non-string, or over 4096 bytes | `{"error":"unsupported","field":"_meta[\"acp-go.dev/route\"].turnNonce"}` |
| Any other member is present | `{"error":"unsupported","field":"_meta[\"acp-go.dev/route\"].<member>"}` |

`missing` names a required key the caller left out, and `unsupported` names a
value that is present and refused; the two are never collapsed. Route validation
runs before the lifecycle prompt correlation is read, so a prompt that gets both
wrong reports the route refusal alone.

A cancel is authorized only by the nonce of the addressed session's current
turn, so a cancel that names another turn — or arrives when no turn is in flight
— fails closed and reaches nothing native. Being a notification, that refusal
carries no response frame.

Every live-turn `session/update` and `_hermes/rawEvent` notification carries the
same exact `{version, turnNonce}` object in its notification `_meta`; raw-event
payloads also carry their structural `sessionId`. Lifecycle and load-history
updates remain outside a turn epoch and omit the envelope.

Every outbound Hermes clarification preserves native metadata and adds
`version`, `sessionId`, `turnNonce`, and its native `requestId` under the route
key. The adapter rejects a pre-existing reserved key. Permission requests keep
their structural session/tool-call correlation and do not use this envelope.

## Media envelope

Initialize always advertises the inbound media bounds the adapter enforces under
the reserved capability key `_meta["acp-go.dev/mediaEnvelope"]`:

```json
{
  "maxBytes": 6291456,
  "maxPromptBytes": 6291456,
  "maxDimension": 0,
  "imageFormats": ["image/png", "image/jpeg", "image/gif", "image/webp"],
  "documentFormats": []
}
```

| Field | Meaning |
|---|---|
| `maxBytes` | Decoded bytes accepted per image. Reports the bound the per-image gate enforces, which is `ImageLimits.MaxInputBytesPerImage` clamped to 7,864,155 bytes. |
| `maxPromptBytes` | Decoded bytes accepted across one prompt. Reports `ImageLimits.MaxInputBytesPerPrompt`. |
| `maxDimension` | Pixels accepted per dimension. Always `0`: Hermes enforces no pixel bound, and `0` means unbounded rather than zero. |
| `imageFormats` | The inbound raster allowlist, in adapter order. |
| `documentFormats` | MIME types mapped to a native document representation. Always an empty array: Hermes has none. |

The byte values track `WithImageLimits`, so the advertisement and the rejection a
host would receive always report the same number. `MaxInputBytesPerImage` set to
`0`, or above 7,864,155, is clamped to 7,864,155 — the largest decoded image one
JSON-RPC frame can carry — and the clamp is what is advertised, because that is
the number a rejection reports. `MaxInputBytesPerPrompt` set to `0` disables the
aggregate and is advertised as `0`; the per-prompt cap of 64 handoff-form blocks
bounds the read work instead. Hermes'
25 MiB native `image.attach_bytes` cap is looser than the policy defaults, so no
native ceiling tightens these values and no `native_envelope_exceeded` verdict
exists on this adapter. The envelope describes adapter bounds only; whether a
selected model accepts an image at all stays a prompt-time result.

## Local handoff

When `WithInputHandoffRoot` is set, initialize additionally advertises
`_meta["acp-go.dev/handoff"] = {"version":1}`, and image blocks may use the
[local handoff form](/docs/core/prompt-streaming#local-handoff-image-input) with the
per-block envelope:

```json
{
  "_meta": {
    "acp-go.dev/handoff": {
      "version": 1,
      "digest": "<sha256 hex>",
      "sizeBytes": 123456
    }
  }
}
```

The advertisement is the host's confirmation that its option reached this
adapter: without a configured root the key is absent and every handoff-form
block is rejected `invalid_handoff`. The envelope accepts exactly those three
fields on a `session/prompt` image block and is read nowhere else.

## Lifecycle extension

Hermes implements version 1 of the `acp-go.dev/lifecycle` extension. A client
sends `{"version":1}` under that key in the `initialize` request `_meta`;
the `acp-go.dev/lifecycle` answer is placed on
`InitializeResponse._meta` and advertises the facts proven by the active
execution mode. With no capability, the key
is omitted from the response and no lifecycle envelope, correlation read, or
lifecycle fact exists on the connection at all.

Hermes reports `updatesOutsidePrompt: true` and an empty `activityKinds` list.
The native gateway publishes no structured activity registry, so no update
this adapter emits carries an activity a lifecycle consumer could track.
Authoritative quiescence is advertised only with a host authority whose process
handle proves whole-tree terminality; its source is `process-containment`.

Prompt requests carry a version-1 submission correlation value under the
lifecycle key:

```json
{"version":1,"submission":{"submissionId":"opaque","clientNonce":"opaque"}}
```

`version` and `submission` are the only members, and `submission` carries
exactly `submissionId`, `clientNonce`, and an optional `runId`. The refusal
splits the same way the route key's does, on the same two verdicts:

| Cause | `data` |
|---|---|
| The key is absent while version 1 is negotiated | `{"error":"missing","field":"_meta[\"acp-go.dev/lifecycle\"]"}` |
| The key is present where it has no meaning — every surface but `initialize` and `session/prompt`, or a prompt on a connection that negotiated nothing | `{"error":"unsupported","field":"_meta[\"acp-go.dev/lifecycle\"]"}` |
| The value is malformed | `{"error":"unsupported","field":"_meta[\"acp-go.dev/lifecycle\"].<member path>"}` |

Both fire before the prompt is dispatched, so no frame reaches Hermes.

Permission and elicitation requests carry the action identity
and owner established in the ordered stream. The lifecycle key is rejected on
every other inbound method. The events themselves ride `session/update`
notifications — see [Updates](/docs/reference/updates#lifecycle-envelopes).

## Request metadata

Lifecycle requests accept:

```json
{
  "_meta": {
    "hermes": {
      "options": {
        "model": "provider/model",
        "env": {
          "HOST_SESSION_TOKEN": "session bearer"
        },
        "extraPathDirs": ["/absolute/operation/bin"]
      },
      "rawEvent": {
        "enabled": false
      }
    }
  }
}
```

| Field | Meaning |
|---|---|
| `options.model` | Selects the `provider/model` pair for the session. On a load or resume that reuses a live session it replaces the next prompt's selection, and a value that is not provider-qualified fails naming `_meta.hermes.options.model` — see [Models And Config](/docs/features/models-config). |
| `options.effort` | Selects the reasoning effort the session runs at: `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`, or `ultra`. It is bound natively at session creation, restore, and fork, and a value outside that vocabulary fails naming `_meta.hermes.options.effort` — see [Models And Config](/docs/features/models-config). |
| `options.env` | Per-session environment variables injected into only that session's Hermes process. Blocked names are listed below. |
| `options.extraPathDirs` | Ordered absolute native directories placed first for that process and restored first in actual local terminal commands after login/profile startup. |
| `rawEvent.enabled` | Opt the session into `_hermes/rawEvent` notifications. |

No other option keys are accepted; any unsupported field fails with an
invalid-params `{"error":"unsupported"}` response.

Session `env` names are checked in sorted key order on every establishing
request, so the first refusal is the same each time. A key is accepted when
it is non-empty and free of `=` and NUL and its value is free of NUL; case is
not a rule, so `https_proxy` and `HTTPS_PROXY` are two ordinary variables.
Blocked names fail as `{"error":"unsupported","field":"_meta.hermes.options.env.<key>"}`
naming the key exactly as sent: `PATH`, `NODE_OPTIONS`, `BASH_ENV`, `ENV`, any `LD_` or `DYLD_` prefix, `HERMES_HOME`, `HERMES_DASHBOARD_SESSION_TOKEN`, `ACP_GO_HERMES_PATH_DIR_*`, and `ACP_GO_HERMES_INTERNAL_*`. All but the adapter's own
namespace compare through the platform identity, exact on Unix and
case-insensitive on Windows; the adapter namespace is refused under every
spelling. Two keys that resolve to one variable under that identity fail as
`{"error":"ambiguous","field":"_meta.hermes.options.env.<later key in sorted order>"}`.
An empty value is delivered as `KEY=`. `ValidateHermesSessionMeta` runs this
parsing on a `_meta` map without an agent, so a host can check a request
before sending it.

`options.extraPathDirs` accepts both the direct Go `[]string` form and the
`[]any` form produced by JSON decoding. It preserves order and duplicates and
deep-clones the list. A non-string, empty, relative, or path-list-separator
entry fails closed naming the exact
`_meta.hermes.options.extraPathDirs[i]` field. The same strict decoding applies
to new, load, resume, and fork lifecycle requests. A raw session `env.PATH`
fails naming `_meta.hermes.options.env.PATH`; `env.BASH_ENV`, `env.ENV`, and the
private `env.ACP_GO_HERMES_PATH_DIR_*` and `env.ACP_GO_HERMES_INTERNAL_*`
namespaces fail likewise. Top-level
`WithEnv` remains the separate static native-base environment surface, but
reserves the latter three names. Managed execution composes PATH directly and
sends none of them through the host authority. In ordinary execution the
private values are absent from the resulting command environment. They may
pass through an installed Bash-script `hermes` launcher
into its immediately exec'd Python gateway so the later snapshot Bash can
consume them; the carrier contains validated directory names and no session
credentials. Windows native directories are converted to Git Bash form without
executing a helper from PATH.

## Response metadata

Advertised model config options carry two per-model `_meta.hermes` fields:
`modelId`, the qualified `provider/model` selection value, and
`supportedEffortLevels`, the reasoning levels of the
[effort selector](/docs/features/models-config#effort-selector), which Hermes
takes for every model and clamps to what the provider accepts. Hermes' model
catalogue answers a model id, a display name, and a per-model capability map
naming `fast` and `reasoning`, alongside per-provider pricing and featured
hints. It advertises no limits or modalities, so nothing else appears in a
config option. The context window a session reports in its usage updates comes
from the completion Hermes returns, not from this catalogue.

A successful `session/prompt` response carries `_meta.hermes.messageId` and
`_meta.hermes.outcome` under the Hermes namespace, plus `_meta.hermes.stopReason`
where a v1 stop reason names that outcome:

```json
{
  "_meta": {
    "hermes": {
      "messageId": "history-2",
      "outcome": "success",
      "stopReason": "end_turn"
    }
  },
  "stopReason": "end_turn",
  "usage": { "inputTokens": 22476, "outputTokens": 20, "totalTokens": 22496 }
}
```

`messageId` is the replay-stable `history-N` identity of the latest finished
assistant and is emitted only after the snapshot containing the same terminal
identity commits. `outcome` is the outcome the commit recorded for that turn,
derived from the finish reason Hermes reported: `success`, `limit`, `refused`,
`cancelled`, or `failed`. `stopReason` is omitted rather than emitted empty,
which is what happens on an outcome no v1 stop reason names. A cancelled turn
answers `stopReason: "cancelled"` with no `_meta` at all. Usage updates carry
none of these.

Every session lifecycle response — `session/new`, `session/load`,
`session/resume`, and the fork extension — carries the session's own
`_meta.hermes` snapshot:

| Field | Meaning |
|---|---|
| `nativeSessionId` | The native Hermes session id this ACP session is bound to. |
| `model` | The selected `provider/model` value sent to Hermes, present when one is bound. |
| `modelId` | The same value under the config-option spelling. |

The `initialize` response advertises the adapter's own surfaces under
`agentCapabilities._meta.hermes`:

| Key | Meaning |
|---|---|
| `fork` | The unstable fork extension: its method name and its request/response payload shapes. |
| `elicitation` | The unstable elicitation surface: its scope and the ACP v1 track it follows. |
| `rawEvent` | The `_hermes/rawEvent` notification: its method, the request field that enables it, its byte ceiling, and that it is off by default. |
| `sessionStore` | The durable store format and the key shape addressing it. |
| `providerAuth` | The provider-auth surface, present only when a provider-auth root is configured. |

The reserved `acp-go.dev/*` literals sit beside that namespace rather than inside it: see
[Media envelope](#media-envelope) and
[Lifecycle extension](#lifecycle-extension).
