## Stable methods

| Method | Behavior |
|---|---|
| `initialize` | Advertises capabilities; records client capabilities. |
| `authenticate` | Rejected — no auth methods advertised. |
| `logout` | No-op. |
| `session/new` | Start a session with a fresh wrapper generation and, by default, an isolated native home. |
| `session/load` | Hydrate, resume, and replay `session.history`. |
| `session/resume` | Hydrate and resume without replay. |
| `session/list` | List stored sessions. |
| `session/prompt` | Run one native turn and stream updates. |
| `session/cancel` | Cancel the in-flight turn. |
| `session/close` | Close the session and stop its process. |
| `session/delete` | Tombstone the store, cancel and settle any active turn, then delete the native session and destroy its generation. |
| `session/set_config_option` | Apply a config option such as `model`. |

## Provider-auth extension methods

These seven session-scoped legs broker provider OAuth through the
`hermes serve` REST auth API. They are advertised — and answer — only while
`-provider-auth-root` and `-shared-hermes-home` name usable durable directories;
otherwise every one returns method-not-found.

| Method | Params | Result |
|---|---|---|
| `_hermes/auth/methods` | `{sessionId}` | `{providers, generation}` |
| `_hermes/auth/authorize` | `{sessionId, providerId, connectionId, methodsGeneration, method, authorizeRequestId, inputs?}` | `{interaction, url?, message, userCode?, callbackInput?, flowId, flowExpiresAt, pollIntervalMs?}` |
| `_hermes/auth/callback` | `{sessionId, providerId, method, flowId, input}` | `{flowId}` |
| `_hermes/auth/status` | `{sessionId, providerId, flowId}` | `{flowId, state, expiresAt?, reason?}` |
| `_hermes/auth/cancel` | `{sessionId, providerId, flowId}` | `{flowId}` |
| `_hermes/auth/inventory` | `{sessionId}` | `{entries}` |
| `_hermes/auth/disconnect` | `{sessionId, providerId, connectionId, bindingGeneration}` | `{}` |

Every request object is closed: an unknown, duplicate, or missing field is
rejected with `-32602` naming the field path. `connectionId` is minted by the
host and enters durable values-free lineage, so it is bounded where it enters:
at most 128 bytes drawn from `A-Z`, `a-z`, `0-9`, `-`, and `_`. A value outside
that shape is `-32602` on `connectionId`. Every leg failure is
`hermes_auth_failed` (`-32000`) with a closed `cause`, and no native message
text ever crosses. See [Authentication](/docs/features/authentication).

## Error shapes

Caller errors are invalid params (`-32602`) carrying `{"error", "field"}`. The
shapes below are uniform across every method that can produce them:

| Cause | `data` |
|---|---|
| A required reserved key the caller omitted | `{"error":"missing","field":"<path>"}` |
| An unknown, misplaced, or malformed value | `{"error":"unsupported","field":"<path>"}` |
| A `cwd` that is not an absolute path — relative or empty — on `session/new`, `session/load`, `session/resume`, or `_hermes/session/fork` | `{"error":"unsupported","field":"cwd"}` |
| An `additionalDirectories[N]` entry that is not an absolute path | `{"error":"unsupported","field":"additionalDirectories[N]"}` |
| Params that cannot be decoded, or that fail validation as a whole | `{"error":"unsupported","field":"params"}` |

An *empty* `cwd` is not an absolute path and takes the `cwd` verdict, but on the
JSON-RPC transport the pinned ACP SDK's own request validation rejects it first
for `session/new`, `session/load`, `session/resume`, and the fork route, so a
wire caller sees the `params` refusal above. The `cwd` verdict is what an
embedding host calling the `Agent` methods directly receives.
| A session-scoped method addressed to an unknown, closed, or deleted session | `{"error":"unknown session","field":"sessionId"}` |
| An SSE or ACP-transport MCP server | `{"error":"unsupported","field":"mcpServers[N]","server":"<name>"}` |
| An MCP server declaring no transport | `{"error":"no_transport","field":"mcpServers[N]"}` |

A failed prompt turn is `hermes_turn_failed` (`-32603`) carrying a `cause` of
`process_exit`, `transport`, `provider`, or `timeout` and the real native cause
in `message` — see [Prompt and streaming](/docs/core/prompt-streaming). A
provider-auth leg failure is `hermes_auth_failed` (`-32000`).

Every other internal error the adapter can produce is `-32603` with the
JSON-RPC constant `Internal error` as its message and exactly one token from
this closed vocabulary in `data.error`. The payload never carries a `message`
member, Go error text, or native Hermes text; a more specific fact is a closed
`class` or `cause` token instead.

| Token | Condition | Additional members |
|---|---|---|
| `hermes_invalid_options` | The agent was built from an option set it will not serve under. `NewAgent` returns no error, so the verdict is delivered on the wire at `initialize` and every session-establishing method. The validation prose stays on the agent's own error value, which the embedding host reads. | none |
| `hermes_restore_failed` | `session/load` or `session/resume` found a store entry for the session that could not be restored — an unreplayable snapshot or an unsupported store format. The entry is neither deleted nor tombstoned. | none |
| `hermes_runtime_unavailable` | A native incarnation this session needs is gone and its process tree is still alive and un-containable, so no replacement can start. A runtime that merely died is never this token: the next explicit operation starts one replacement. | none |
| `hermes_session_poisoned` | The session latched on an unrecoverable native fact and refuses every operation but `session/close` and `session/delete`. | `cause`, one of `runtime_resume_failed`, `native_session_id_drift`, `mcp_reload_failed`, `runtime_fence_failed`, `missing_live_session_mapping`, `terminal_snapshot_failed` |
| `hermes_internal_failure` | Every failure the adapter cannot classify above. | optional `class`, one of `lifecycle_overlap`, `lifecycle_violation`, `route_correlation`; `lifecycle_violation` adds a `cause` from the lifecycle reducer's closed violation vocabulary |

## Extensions and unsupported methods

`session/set_mode` returns method-not-found. The only native extension method is
`_hermes/session/fork`; the only native notification is `_hermes/rawEvent` (see
[Raw events](/docs/features/raw-events)).

Command listing is intentionally silent in v1. MCP accepts `stdio` and `http`
server definitions; `sse` and ACP-transport definitions are rejected during
session start.
