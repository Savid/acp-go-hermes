title: CLI
description: Every flag the acp-go-hermes command accepts.

```sh
acp-go-hermes [flags]
```

## Standalone execution

The command runs Hermes as its own operating-system account. It captures the
ambient environment once, removes adapter-private and native-state variables,
and uses the resulting environment for executable lookup and every session.
Host-managed execution is available only through the embedded Go API.

## Flags

| Flag | Meaning |
|---|---|
| `-path` | Hermes executable path; falls back to `hermes` on `PATH` when unset. |
| `-scratch-dir` | Parent directory for ephemeral session scratch; empty means the system temp directory. |
| `-home` | Unsupported. Use `-scratch-dir` for ephemeral state or `-shared-hermes-home` for the explicit official-Hermes durable mode. |
| `-shared-hermes-home` | Absolute supported local-filesystem path used as the exact durable `HERMES_HOME` by all per-session Hermes processes of this adapter. |
| `-provider-auth-root` | Absolute durable directory that houses the values-free provider-auth ledger. Requires `-shared-hermes-home`. |
| `-model` | Default model value passed as `provider/model`. |
| `-seed-file` | Seed a file into each session's config root as `<relpath>=<hostpath>` (repeatable). |
| `-debug` | Enable debug logging on stderr. |
| `-version` | Print the adapter version and exit. |

`-seed-file` reads the host file at startup and writes its contents to
`<relpath>` under the session config root before Hermes launches. Relative
paths are confined to that root; absolute paths, `..` segments, and empty keys
are rejected. Keep secrets out of seeded files and reference them by
environment-variable indirection instead.

## Example

Pointing Hermes at a LiteLLM gateway:

```sh
acp-go-hermes -seed-file config.yaml=./hermes-config.yaml
```
