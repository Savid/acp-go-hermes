# Lifecycle extension

Hermes implements version 1 of `acp-go.dev/lifecycle`. A client offers
`{"versions":[1]}` under that key in `initialize` `_meta`. When version 1 is
selected, the initialize response advertises the facts proven by the active
containment configuration.

Hermes reports `updatesOutsidePrompt: true` and an empty `activityKinds` list.
The native gateway has no complete structured activity registry, so todo or plan
updates are not promoted to lifecycle activities. Authoritative quiescence is
advertised only when process isolation can prove whole-tree vacancy; its source
is `process-containment`.

Lifecycle envelopes ride only identity-only `session_info_update`
notifications. Each envelope names one stream incarnation and a contiguous
sequence. The first event is a complete `lifecycle_snapshot`; later events are
`prompt_accepted`, `state_update`, `action_update`, and, after a proven
containment boundary, `quiescence_update`. Hermes emits no `activity_update`.

Prompt requests carry a version-1 submission correlation value. Permission and
elicitation requests carry the action identity and owner established in the
ordered stream. The lifecycle key is rejected on every other inbound method.

Sequence numbers are claimed before delivery. A delivery failure fences that
incarnation rather than reusing its sequence. Exact retransmission is
idempotent; gaps, conflicting duplicates, stale incarnations, malformed event
shapes, and post-terminal mutation fail closed.

Prompt completion proves only foreground `idle`. A workflow can rely on
quiescence only when the initialize answer advertises authoritative quiescence
and a later `quiescence_update` covers the final lifecycle watermark. Cancel,
close, runtime loss, and timeout end the native incarnation; active work is
contained before its stream is fenced.
