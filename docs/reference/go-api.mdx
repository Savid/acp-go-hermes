# Go API

Primary entry points:

```go
agent := hermesacp.NewAgent()
err := hermesacp.Serve(ctx, input, output)
```

Common options include `WithExecutablePath`, `WithHome`, `WithDefaultModel`,
`WithEnv`, OpenTelemetry provider options, `WithSessionStore`,
`WithConcurrencyLimits`, `WithSeedFiles`, and `WithTurnTimeout`.

`WithTurnTimeout(time.Duration)` bounds how long a single native turn may run
before the adapter aborts it and fails the prompt with the uniform
`hermes_turn_failed` error whose `cause` is `timeout`. The default of `0`
disables the deadline. A timeout is a failure, not a user cancel, so it is never
reported as the `cancelled` stop reason.

`WithSeedFiles(map[string]string)` maps relative paths to file contents that the
adapter writes into each session's isolated Hermes config root before hermes
launches, so hermes reads them as its own config (for example `config.yaml`).
Every session is seeded fresh. Paths are confined to that root: absolute paths,
`..` segments, and empty keys are rejected at session start with the uniform
unsupported error. Keep secrets in `WithEnv` and reference them from seeded
files by env-var indirection (hermes `key_env`), never inline.

`config.yaml` is the one file the adapter itself authors, because it writes the
`mcp_servers` block hermes reads from session MCP servers. Per the family merge
rule, a seeded `config.yaml` is deep-merged with the adapter's managed
`mcp_servers` on top: the adapter wins for `mcp_servers`, and the seed supplies
everything else (for example a `model` block). All other seeded files are
written verbatim.

Session `HermesOptions` include `WithHermesModel`, `WithHermesEnv`, and
`WithHermesOutputSchema`.

`WithHermesOutputSchema` is accepted for API symmetry but fails session start
with the uniform unsupported structured-output error. Native auth material must
be supplied through Hermes' own environment/configuration, not the ACP store.
