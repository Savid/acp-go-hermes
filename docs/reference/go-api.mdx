The public API lives in package `hermesacp`. This page indexes the surface; exact
signatures and per-symbol contracts are on
[pkg.go.dev](https://pkg.go.dev/github.com/savid/acp-go-hermes).

## Entry points

```go
agent := hermesacp.NewAgent(opts...)
err := hermesacp.Serve(ctx, input, output, opts...)
```

`NewAgent` builds an `Agent` you own; `Serve` runs the ACP loop over a
reader/writer pair.

`ErrProcessContainmentIncomplete` is the stable `errors.Is` discriminator returned
when the selected native containment boundary cannot be completed. `Serve`
returns an `Agent.Close` error carrying this sentinel even when the stream
loop would otherwise return normally or with context cancellation. A host that
receives it must retain or quarantine any resources the native process tree may
still reach.

## Agent options

| Option | Purpose |
|---|---|
| `WithExecutablePath` | Path to the `hermes` binary (falls back to `hermes` on `PATH`). |
| `WithProcessIsolation` | Optional. Opts into the hardened Linux identity boundary: nonzero non-root UID/GID and a complete replacement environment for native Hermes processes. The embedded supervisor stays a distinct trusted root; only `hermes serve` receives the configured identity, with supplementary groups cleared. Linux-only and fail-closed. Omitting it runs Hermes as the adapter's own identity. |
| `WithScratchDir` | Sole parent directory for all ephemeral on-disk scratch (isolated per-session homes, sqlite temp dirs, process temp roots); empty means the system temp directory, created `0700` when missing. |
| `WithHome` | Unsupported. Use `WithScratchDir` for isolated ephemeral state or `WithSharedHermesHome` for the explicit official-Hermes durable mode. |
| `WithSharedHermesHome` | Absolute, already-clean, supported local-filesystem path used as the exact durable `HERMES_HOME` by each per-session official Hermes process of this adapter. The adapter claims the home root exclusively for the lifetime of those processes and refuses to start when another adapter already holds it. Native database/auth state is shared; processes, environments, events, and wrapper controls remain separate. With `WithProviderAuthRoot` also set, the adapter resolves this path's symlinks and uses the resolved path everywhere instead. |
| `WithDefaultModel` | Default `provider/model` for new sessions. |
| `WithEnv` | Static Agent-scoped environment overlaid on `ProcessIsolation.BaseEnvironment`, or on the captured sanitized ambient environment in ordinary mode, for Hermes executable lookup, version probing, and each `hermes serve` process. This is the only API that may set the native base `PATH`. `BASH_ENV` and `ACP_GO_HERMES_PATH_DIR_*` are reserved for the adapter's terminal PATH carrier. |
| `WithSeedFiles` | Files written into each session's config root before launch. |
| `WithSessionStore` | Durable `SessionStore` for persistence. |
| `WithSessionStoreLoadTimeout` | Bound on each store read (default 10s); writes use a fixed 60s bound. |
| `WithConcurrencyLimits` | `ConcurrencyLimits{MaxActiveSessions, MaxConcurrentClientCalls}`. |
| `WithImageLimits` | Decoded-byte limits for image prompt input; all four fields default to 6 MiB when omitted. |
| `WithProviderAuthRoot` | Absolute durable directory holding the values-free provider-auth ledger. Requires `WithSharedHermesHome`; supplying it alone fails `initialize` with `-32603`. |
| `WithInputHandoffRoot` | Absolute read-only root under which the host materializes local handoff image files; unset leaves the handoff prompt form rejected. |
| `WithTurnTimeout` | Per-turn deadline; `0` disables (see below). |
| `WithRuntimeResourceHooks` | Host admission hooks for native-process roots and adapter scratch roots. |
| `WithDarwinBestEffortContainment` | Explicitly accept Darwin process-group containment and its escaped-descendant, marker-scrubbing, and PGID-reuse risks. Rejected off Darwin, and rejected when combined with `WithProcessIsolation`. |
| `WithAgentName` / `WithAgentTitle` / `WithAgentVersion` | Advertised agent identity. |
| `WithLogger` | `*slog.Logger` for adapter diagnostics. |
| `WithTracerProvider` / `WithMeterProvider` / `WithTextMapPropagator` | OpenTelemetry providers. |

`ProcessIsolation.IdentityLock` and `ProcessIsolation.AuthorityDomain`
optionally accept opaque host capabilities with `Duplicate() (*os.File, error)`
for the already-held canonical UID lock and shared `domain.lock` lease. Each
capability keeps ownership of its original descriptor; caller-owned duplicates
reach only the trusted supervisor, which validates the named inodes, held locks,
and strict matching domain record and protects them with checked `FD_CLOEXEC`.
Set both fields together for
host-borrowed authority or leave both nil for standalone domain, disposition,
and UID-lock acquisition. A mixed nil/non-nil pair fails closed. Native
processes receive neither capability nor descriptor.

## Provider auth

`WithProviderAuthRoot` enables the values-free provider-auth ledger only when
`WithSharedHermesHome` also names the official native credential residence.
The adapter never exposes a public credential type and never reads, copies, or
returns native credential bytes. Shared mode binds one exact Hermes version and
one managed MCP/seed configuration to a durable local filesystem; mismatches
fail before launch. Because one adapter holds the home root exclusively, the
native `auth.json` in that residence has exactly one writing adapter at a time
even when separate ledger roots name the same residence, and within that adapter
the per-provider fence is keyed by the residence too, so agents configured with
different ledger roots and one shared home still serialize. It rejects `dashboard.turn_isolation=true` and
`model.persist_switch_by_default=true` because those settings mutate
process-global shared state.

Enabling the pair rewrites the shared home the caller supplied. The agent
creates that directory `0700` when it is absent, resolves every symlink in the
path, and uses the resolved path from then on — as `HERMES_HOME` and the shared
XDG root of each native process, as the root the exclusive home-root claim
fences, and as the input to the ledger's per-home key. A host that configured
the home through a symlink will not see its own spelling in any of those
places.

A misconfiguration is not always a silent degradation. Omitting
`WithProviderAuthRoot` leaves the seven methods unadvertised and answering
`-32601`; an absolute pair the agent cannot prepare logs a warning and does the
same. A relative ledger root, a relative or unclean shared home, or
`WithProviderAuthRoot` without a shared home is instead a construction failure
that every `initialize` reports as `-32603`.

Provider auth also requires the per-process browser-launcher shim.
`_hermes/auth/authorize` refuses before any native call when the session's
process has none, with `hermes_auth_failed`, `cause: "policy"`, and
`retryable: false`. Windows has no shim and no shared home, so no session there
can reach a login.
See [Authentication](/docs/features/authentication).

`WithTurnTimeout(time.Duration)` bounds how long a single native turn may run
before the adapter interrupts it, completes its selected native containment
boundary, and fails the prompt with the uniform
`hermes_turn_failed` error whose `cause` is `timeout`. The default `0` disables
the deadline. A timeout is a failure, not a user cancel, so it is never reported
as the `cancelled` stop reason — see
[Prompt streaming](/docs/core/prompt-streaming).

Linux completion under an explicit policy authoritatively empties the native
tree. Ordinary same-identity completion covers exactly the direct child and the
process group the adapter started, and makes no claim about work that left that
boundary. Darwin best-effort completion means only direct-child reaping plus
absence of the captured original process group; it does not establish that
escaped descendants are gone. The explicit hardened policy is Linux-only and is
refused elsewhere rather than downgraded.

`WithImageLimits(ImageLimits)` replaces all four image limits:
`MaxInputBytesPerImage`, `MaxInputBytesPerPrompt`,
`MaxOutputBytesPerImage`, and `MaxOutputBytesPerToolCall`. Limits count decoded
bytes. Omitting the option defaults every field to 6 MiB (6,291,456 bytes);
zero in a supplied struct disables that adapter policy limit, and a negative
field is rejected at agent construction. Hermes implements image prompt input;
it does not emit typed image output. The `MaxOutputBytesPerImage` and
`MaxOutputBytesPerToolCall` fields exist for API symmetry but Hermes never
consults them.

`WithInputHandoffRoot(dir string)` names the absolute directory under which a
co-located host has written handoff image files, enabling the
[local handoff form](/docs/core/prompt-streaming#local-handoff-image-input) and the
`acp-go.dev/handoff` advertisement. It is a read root, not a scratch root: the
adapter resolves, reads, and digest-verifies files there and never writes, moves,
or removes anything, so it does not compete with `WithScratchDir` for ephemeral
materialization. A relative path is rejected at agent construction. Omitting the
option leaves every handoff-form block rejected as `invalid_handoff` and the
capability unadvertised.

`RuntimeContainmentMode` reports `authoritative`, `shared_identity`,
`best_effort`, or `unavailable`. Embedded hosts read the resolved mode from
`Agent.ContainmentMode()`, and the `ObserveContainment` runtime-resource hook
reports it once at agent construction. `shared_identity` is the ordinary default reported on
every supported platform when `WithProcessIsolation` is omitted; it is
non-authoritative, so it publishes no provider-descendant snapshots and makes no
whole-tree quiescence or credential-separation claim. Best-effort snapshots are
suppressed for the same reason, including zero-valued ones. `unavailable` means
native launch fails closed, which is what an explicit policy reports on a
platform that cannot host it. Only `authoritative` publishes inventory.

`WithSeedFiles` confines paths to the config root: absolute paths, `..`
segments, and empty keys are rejected at session start. `config.yaml` is the one
file the adapter itself authors (to carry the `mcp_servers` block); a seeded
`config.yaml` is deep-merged with the adapter's managed `mcp_servers` on top. All
other seeded files are written verbatim.

## Request builders

| Builder | Produces |
|---|---|
| `NewSessionRequest` / `LoadSessionRequest` / `ResumeSessionRequest` / `ForkSessionRequest` | Session lifecycle requests. |
| `PromptRequest` / `TextPromptRequest` | Prompt requests carrying a required per-turn nonce. |
| `CancelRequest` | Active-turn cancellation carrying the same nonce. |
| `StdioMCPServer` / `HTTPMCPServer` | MCP server definitions. |
| `SetModelRequest` / `SetConfigOptionRequest` | Config-option requests. |
| `ListSessionsRequest` | Session listing, with `WithListSessions*` options. |

Session requests take options such as `WithSessionMCPServers`,
`WithSessionAdditionalDirectories`, `WithSessionMeta`, `WithSessionHermesOptions`,
and `WithSessionRawEvents`.

`WithSessionMeta` and `WithListSessionsMeta` carry host-supplied `_meta` maps.
The `acp-go.dev/*` namespace is reserved: its envelopes are stamped by this
package and read by every consumer, so a caller key inside it is refused rather
than merged or overwritten. Neither builder returns an error, so the refusal is
a panic — passing a reserved key is a program naming a namespace that is not its
own. Host namespaces and `_meta.hermes` merge as before.

`PromptRequest(sessionID, turnNonce, blocks...)` and
`TextPromptRequest(sessionID, turnNonce, text)` require a fresh, unguessable
nonce of at most 4096 bytes for every turn. `CancelRequest(sessionID,
turnNonce)` reuses it only for that active turn. Builders fail closed by
omitting the route envelope when given an empty or oversized nonce, so the
adapter rejects the resulting request.

`RuntimeResourceHooks` supplies `AcquireNativeRoot`, `ReserveScratchRoot`,
`ObserveProcess`, `ObserveProcessSnapshot`, `ObserveStartupStage`, and
`ObserveContainment`.
Admission callbacks receive `runtime`, `session`, `prompt`, or `discovery`; nil
callbacks leave standalone operation unbounded. Hermes reserves the isolated
session home before creating it, holds the native permit for the one
`hermes serve` tree, and releases the reservation only after clean shutdown and
root deletion. Linux process snapshots include the dedicated per-session
subreaper plus every currently owned native descendant. Descendant snapshots
require authoritative containment, so ordinary `shared_identity` execution
produces none on any platform; startup observations distinguish spawn,
readiness, configuration, and native session creation.

## Session store

The `SessionStore` interface is `Append`, `Load`, `Replace`, `Delete`,
`ListSessions`, and `ListSubkeys`. `NewInMemorySessionStore` returns a built-in
implementation. Supporting types: `SessionKey`, `SessionSummary`,
`SessionStoreReplacement`, and the `SessionStoreMainSubpath` /
`SessionStoreFormat` constants.

`InspectSessionStoreTerminalState(logicalSessionID, entries)` strictly
validates exactly one current-format main snapshot and returns its
`SessionStoreTerminalState`. The `MessageID` is empty before the first completed
assistant turn and otherwise contains the latest replay-stable `history-N`
identity.

## Session Hermes options

`HermesOptions` carries the `Model`, `Env`, `ExtraPathDirs`, and `OutputSchema`
fields. `NewHermesOptions` builds one from `WithHermesModel`, `WithHermesEnv`,
`WithHermesExtraPathDirs`, and `WithHermesOutputSchema`.

`ExtraPathDirs` is an ordered, cloned list of absolute native directories placed
ahead of the base `PATH` for both that session's `hermes serve` process and its
actual local terminal commands. Order and duplicates are semantic. Empty,
relative, or path-list-separator-bearing entries are rejected with the exact
indexed metadata field. Session `Env` cannot contain `PATH`, `BASH_ENV`, or an
`ACP_GO_HERMES_PATH_DIR_*` key. `WithEnv` and
`ProcessIsolation.BaseEnvironment` also reserve the latter two namespaces, and
an ambient `BASH_ENV` is scrubbed at launch. The dedicated ordered field is the
sole session-scoped PATH authority.

Hermes executable resolution and version probing see only the static base
environment. The launched process sees operation directories first, the
browser-launcher shim second when present, and the captured native base `PATH`
last. For native terminal execution the adapter-owned Bash hook runs after the
login profile has rewritten PATH and restores the operation directories first
before Hermes records its shell snapshot. It then removes `BASH_ENV` and every
private carrier variable from that snapshot and from the resulting terminal
command environment. An installed `hermes` executable may itself be a Bash
script that immediately execs the Python gateway; the process-local carrier is
preserved through that launcher so the later snapshot Bash can consume it. The
values are validated directory names, not credentials, and remain inaccessible
through the public environment surfaces. On Windows the hook translates
validated drive and UNC paths to Git Bash form without resolving or executing a
command from PATH.

Setting a schema — through the field or `WithHermesOutputSchema` — is accepted
for API symmetry but fails session start with the uniform unsupported-field
error.
