title: MCP
description: Attach MCP servers to a session and how the adapter forwards them to Hermes.
---

Attach Model Context Protocol servers to a session so Hermes can call their
tools. Servers are supplied by the host per session; the adapter forwards them to
Hermes and never exposes a public MCP route of its own.

## Supported transports

Session lifecycle requests accept `stdio` and streamable `http` MCP server
definitions. `sse` and ACP-transport MCP server definitions are rejected during
session start.

| Transport | Accepted | Builder |
|---|---|---|
| stdio | yes | `StdioMCPServer` |
| http (streamable) | yes | `HTTPMCPServer` |
| sse | no (rejected at session start) | — |
| acp | no (rejected at session start) | — |

## How servers reach Hermes

The adapter authors the session's `config.yaml` `mcp_servers` block from the
accepted server definitions and writes it into the session's isolated config
root before `hermes serve` launches. When a `config.yaml` is also seeded, the
adapter's managed `mcp_servers` block wins on deep-merge while the seed supplies
the `model` block and everything else — see
[Models and config](/docs/features/models-config).

Hermes snapshots MCP tools while its native process starts. Hosts can keep an
HTTP MCP endpoint disarmed during `session/new` and arm it only for an
authorized turn, so the adapter forces one native `reload.mcp` before the first
prompt reaches the model. The reload is scoped to the live native session and
bounded at two minutes. Cancellation before it completes leaves the reload
eligible for the next authorized turn; any other indeterminate reload failure
poisons the session instead of running with a stale tool surface. A process
created by `session/load` or `session/resume` performs the same one-time reload
before its first continuation.

HTTP header values are never written literally into `config.yaml`. The adapter
generates a distinct `MCP_HEADER_<server-index>_<header-index>` environment
reference under the adapter namespace for every header
and injects the value only into that isolated session process environment. A
caller-supplied environment variable colliding with a generated reserved name
fails session start. The session process and its children can observe their own
environment; cross-session separation therefore comes from one process and
home per ACP session. Separate OS users or containers are required across
hostile same-machine tenants.

```go
req := hermesacp.NewSessionRequest(cwd,
	hermesacp.WithSessionMCPServers(
		hermesacp.StdioMCPServer("files", "mcp-files", []string{"--root", "/work"}, nil),
	),
)
```

<Note>
MCP servers are host-provided and session-scoped. The adapter exposes no public
MCP transport route, and one session's servers are never reachable from another.
</Note>
